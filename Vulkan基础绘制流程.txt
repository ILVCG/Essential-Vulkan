Vulkan将资源分为：1. 缓存	2. 图像
    1. 1 缓存：线性数组，表示不同资源
	类型：VkBuffer
	创建方式：vkCreateBuffer
	描述结构：VkBufferCreateInfo

	类型：VkImage
	创建方式：vkCreateImage

    2.2 图像视图：同缓存视图，描述所用缓存对象格式，范围
	类型：VkImageView

	描述结构：VkImageViewCreateInfo

12. 创建流水线

---------------------------------------------------------------------------------------------
流水线按类型分为两种：
	1. 图形流水线：包含顶点、片元、细分、几何等多个着色器阶段，对应一个流水线布局和多个固定（Fix）函数流水线阶段
	2. 计算流水线：包含一个静态的计算着色器阶段，对应一个刘淑仙布局
---------------------------------------------------------------------------------------------
流水线状态：
	1. 动态状态：提示流水线在运行中观察状态变换情况。
	2. 顶点输入状态：帮助流水线读取和解析用户数据。
	3. 光栅化状态：此状态下，图元被转换为二维图像中颜色、深度等属性的数值信息。
	4. 颜色融混附加专题：源颜色与目标颜色数据的组合。
	5. 视口状态：控制视口变换
	6. 深度模板状态：实现深度测试、模板测试、深度边界测试
	7. 多重采样状态：控制图元在光栅化时反走样机制的实现。
---------------------------------------------------------------------------------------------

    (42) 定义流水线不同阶段的状态对象、
	描述结构：VkPipelineVertexInputStateCreateInfo		//顶点输入状态
		VkPipelineDynamicStateCreateInfo				//动态状态
		VkPipelineInputAssemblyStateCreateInfo			//输入组装状态
		VkPipelineRasterizationStateCreateInfo			//光栅化状态
		VkPipelineColorBlendStateCreateInfo				//颜色融混状态
		VkPipelineViewportStateCreateInfo				//视口状态
		VkPipelineDepthStencilStateCreateInfo			//深度模板状态
		VkPipelineMultisampleStateCreateInfo			//多重采样状态

---------------------------------------------------------------------------------------------

引入同步信号，确保绘制图像的获取操作必须在它已经被渲染到显示输出设备之后，并且已经准备的前提下完成。

14. 队列提交与同步（发送任务）

---------------------------------------------------------------------------------------------
已记录了多个指令到指令缓存中，包括渲染通道信息和图形流水线对象。
接下来需要将指令缓存发送到队列，驱动会开始读取指令缓存并准备调度和执行。
为了高效渲染，指令缓存会被打包为多个批次，若有多个指令缓存，需要设法打包到一个VkCommandBuffer数组中。
Vulkan使用VkFence（类似DX12的ID3D12Fence）确保推送新批次前之前的批次已经处理完成。
VkFence使用vkCreateFence创建，VkFence由VkFenceCreateInfo控制结构描述
指令缓存需要传递给发送对象VkSubmitInfo，该对象包含了一个指令缓存列表和一个VkSemaphore实现帧缓存与交换链图像同步，
并进一步传递给函数vkQueueSubmit，其中包含一个VkQueue对象来包含发送的指令缓存数据，及一个VkFence确保每个指令缓存的发送之间正确同步。
---------------------------------------------------------------------------------------------
    (57) 创建屏障（栅栏）对象
	描述结构：VkFenceCreateInfo
	存储类型：VkFence
	方法：vkCreateFence
    (58) 描述发送对象结构
	描述结构：VkSubmitInfo
			VkSubmitInfo::pNext					//nullptr
			VkSubmitInfo::sType					//此处为VK_STRUCTURE_TYPE_SUBMIT_INFO

Vulkan同步概念补充
1. Event同步
    Event是可重置的二值信号，用于：
	1. 在同一条command buffer里：某点set event，后面某点wait event，中间可以插入其它命令。
	2. 在不同command buffer（甚至同队列先后submit）里：前缓冲vkCmdSetEvent，后缓冲vkCmdWaitEvents，用event把两段GPU 工作串起来，而不必在整条队列上插一个大 barrier。
    相关命令：
	GPU端：	vkCmdSetEvent：执行到这里时，在指定pipeline stage把event设为signaled。
		vkCmdWaitEvents：在指定stage等待一个或多个event，并可附带memory barrier（global/buffer/image），描述wait之后的可见性。
	CPU端：	vkGetEventStatus 		//获取Event状态
		vkSetEvent  				//设置Event状态
		vkResetEvent				//重置Event状态
2. Barrier同步
    Barrier在一条命令缓冲的某条命令位置上声明：
	1. 执行依赖（execution dependency）：即哪些管线阶段（VkPipelineStageFlags）上的工作必须先完成，哪些阶段才能开始。
	2. 内存依赖（memory dependency）：即哪些访问类型（VkAccessFlags）对哪些内存的写/读必须对后续可见（相当于 cache / visibility 的约束）。
    类型：
	1. Global memory barrier		//不关联具体Image / Buffer，整段内存可见
	2. Buffer memory barrier		//指定Buffer区间访问，与Layout无关
	3. Image memory barrier			//指定Image、Subresource区间访问，Layout转换
    相关命令：
	vkCmdPipelineBarrier / vkCmdPipelineBarrier2		//插入内存依赖Barrier
